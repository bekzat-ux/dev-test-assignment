# Заметки

## Одновременное бронирование в PostgreSQL

Проверка слотов и запись должны выполняться в одной транзакции. Транзакция блокирует строку мастера (`SELECT ... FOR UPDATE`), проверяет отсутствие активной записи с учётом семиминутной уборки и вставляет новую запись. В качестве дополнительной защиты можно задать GiST exclusion constraint для мастера и непересекающегося диапазона времени (для сравнения `master_id` потребуется `btree_gist`). Тогда конкурирующий экземпляр дождётся первой транзакции и вернёт `409`, если слот уже занят. Простая проверка перед `INSERT` без блокировки оставит гонку.
